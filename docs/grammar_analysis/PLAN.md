# The Hot Spot 日语文法解析计划

## 快速恢复入口

每次重新开始任务时，先按这个顺序读取：

1. `grammar_analysis/PROGRESS.md`：确认当前集数、已完成字幕块、下一个字幕块编号。
2. 当前集文档：`grammar_analysis/episodes/E##.md`，从末尾继续。
3. 全局文法索引：`grammar_analysis/index/grammar_index.md`，确认哪些文法已经详细说明过。
4. 全局统计：`grammar_analysis/index/grammar_counts.md` 或 `grammar_counts.csv`，继续累计出现次数。

默认处理顺序为 `E01 -> E10`。不要跳集处理，因为“第一次出现”的判定以整部剧的播放顺序为准。

## 目标

输入是 `2/` 目录下 10 集日语 `.srt` 字幕。目标是为每集生成一个 Markdown 文档，逐句解析台词中用到的日语文法；文法在整部剧中第一次出现时给出详细说明，后续出现时只做短注并链接或标注文法编号。最后按文法出现次数做全剧总结。

## 范围定义

### 解析对象

解析所有实际日语台词。以下内容不作为文法统计主体：

- 纯音效或动作说明，例如 `（はなをすする音）`。
- 只有人名或说话人标记的部分，例如 `（清美）`。
- 电视、广播、旁白等说话来源标记本身。

如果一个字幕块中有多位说话人，用台词行拆开处理。字幕中的换行如果只是排版换行，合并为同一句；如果是不同说话人的发话，分开。

### “第一次出现”的判定

以整部剧、按 `E01` 到 `E10` 的顺序判定。某个文法第一次出现时：

- 在当前集文档的“本集新文法详解”中详细说明。
- 在 `grammar_analysis/index/grammar_index.md` 中登记。
- 分配稳定编号，例如 `G0001`、`G0002`。

后续集数或后续句子再次出现同一文法时，不重复长篇说明，只写短注，例如：

```md
- `そっか`：`か` 句末疑问/确认语气，参见 `G0002`。
```

### 统计口径

文法出现次数按“实际出现”计数：

- 同一句中同一文法出现两次，计 2 次。
- 同一字幕块中两句分别出现同一文法，计 2 次。
- 口语缩约和完整形式归入同一主文法，但在变体字段中记录。例如 `ている`、`てる` 归入同一条；`では`、`じゃ` 归入同一条。
- 词汇本身不计作文法；只有涉及助词、活用、句型、语气、接续、授受、敬语、条件、使役、被动等结构时才计入。

## 单集处理流程

### 1. 预处理字幕

对当前集做轻量清理：

- 去掉 SRT 序号和时间轴，但保留字幕块编号和时间，便于回查。
- 去掉不可见格式字符，例如字幕中常见的 `‪`。
- 保留原始日文、说话人、字幕块编号。
- 将一个字幕块拆成一个或多个“台词句”。
- 对纯音效或动作说明标记为“跳过”，不要强行解析。

当前执行批量为每次 200 个字幕块。对白极密集时可在同一轮内分段写入，但进度按 200 块推进。

### 2. 逐句识别文法

每句至少检查这些层面：

- 动词活用：ます形、て形、た形、ない形、意向形、命令形、可能形、被动、使役、使役被动。
- 助词：は、が、を、に、で、と、へ、から、まで、より、も、しか、だけ、くらい、なんか、って 等。
- 句型：のだ/んだ、ことがある、ことになる、ように、ために、はず、わけ、つもり、べき、そう、らしい、みたい 等。
- 接续：から、ので、けど、のに、ながら、たら、なら、と、ても、てもいい、てはいけない。
- 补助动词：ている/てる、てある、ておく/とく、てしまう/ちゃう/じゃう、てみる、てくる、ていく、てあげる、てくれる、てもらう。
- 口语缩约：では->じゃ、ている->てる、ておく->とく、てしまう->ちゃう/じゃう、なければ->なきゃ/なくちゃ、という->って、のだ->んだ、ては->ちゃ。
- 终助词和语气：か、ね、よ、な、ぞ、ぜ、わ、かな、かも、だろう/でしょう。
- 敬语和语体：普通体、丁寧体、尊敬语、谦让语、美化语。
- 省略和倒装：口语中主语、助词、谓语省略时，说明省略恢复后的结构。

### 3. 首次出现文法详解标准

第一次出现的文法条目必须包含：

- 编号：`G0001`。
- 文法名：例如 `た形：过去/完成`。
- 形式：接续方式和常见形式。
- 本句例子：引用当前台词中的最小必要片段。
- 中文解释：核心意义。
- 语感和使用场景：正式/口语、书面/会话、强弱语气。
- 活用或接续细节：前接动词、形容词、名词时如何变化。
- 常用缩约或变体：如果存在，列出并说明。
- 易混点：和相近文法的区别。
- 自造例句：1 到 2 个短句，附中文。
- 首次出现位置：例如 `E01-0003-1`。
- 标签：如 `助词`、`活用`、`口语`、`句型`、`终助词`。

### 4. 非首次出现短注标准

后续出现同一文法时，每处只需要：

- 标出文法编号和名称。
- 说明它在本句中的具体作用。
- 必要时指出口语缩约或省略。

示例：

```md
- `なんない`：`ならない` 的口语音变/缩约，表示“不会变成/不会到……程度”，归入 `G00xx なる/ならない`。
```

### 5. 更新全局索引和统计

每完成一个处理批次后更新：

- `PROGRESS.md`：当前集完成到哪个字幕块，下一个字幕块编号是什么。
- 当前集 `episodes/E##.md`：追加解析内容。
- `index/grammar_index.md`：新增首次出现文法。
- `index/grammar_counts.md` 或 `grammar_counts.csv`：累计次数。

不要等整集结束才更新进度。每 200 个字幕块至少更新一次；若中途分段写入，最终仍以 200 块批次更新进度。

## 进度记录规则

`PROGRESS.md` 是续做任务时的唯一进度真相。每次批次完成后必须更新：

- 当前状态：未开始、进行中、完成、待复核。
- 已完成到的字幕块编号。
- 下一个字幕块编号。
- 本批次新增的文法编号范围，例如 `G0001-G0020`。
- 待复核问题，例如“这句的 `って` 是引用还是主题提示？”。

建议批次记录格式：

```md
| 日期 | 集数 | 处理范围 | 新增文法 | 更新文件 | 备注 |
|---|---|---|---|---|---|
| 2026-06-27 | E01 | 0001-0050 | G0001-G0018 | E01.md, grammar_index.md, grammar_counts.csv | 0001-0002 为音效，跳过 |
```

## 推荐执行节奏

1. 先完成 `E01` 的前 50 个字幕块，建立 `G0001` 开始的文法索引规范。
2. 检查 E01 文档格式是否适合学习；如果太长，后续改为“逐句短注 + 文法详解集中在索引”。
3. E01 完成后，生成本集统计和复盘。
4. 按同样方式依次完成 E02 到 E10。
5. 全部完成后，生成全剧总表：
   - 按出现次数降序。
   - 按文法类型分组。
   - 高频口语缩约清单。
   - 建议学习顺序。

## 完成标准

每一集完成必须满足：

- 所有字幕块都被处理或明确标记为跳过。
- 所有实际台词句都有文法解析。
- 本集首次出现的新文法已经写入全局索引。
- 本集文法次数已经计入全局统计。
- `PROGRESS.md` 中该集状态改为完成。

全剧完成必须满足：

- `E01.md` 到 `E10.md` 均存在且状态为完成。
- `grammar_index.md` 包含所有首次出现文法的详细说明。
- `grammar_counts.md` 按全剧出现次数降序排列。
- `grammar_counts.csv` 可以用于后续排序或二次整理。
- `PROGRESS.md` 的总状态为完成。
